question - what is difference b/w l7 load balancer and l4 load balancer in azure or application gateway and load balancer in azure
ans - L7 Load Balancer (Application Gateway) operates at the application layer (Layer 7) of the OSI model. 
It can make routing decisions based on the content of the HTTP/HTTPS requests, such as URL paths, host headers,
 and cookies. It is ideal for web applications and can provide features like SSL termination, session affinity, 
 and Web Application Firewall (WAF) capabilities. 
L4 Load Balancer (Azure Load Balancer) operates at the transport layer (Layer 4) of the OSI model.
 It routes traffic based on IP address and port without inspecting the content of the traffic. 
 It is suitable for non-HTTP workloads, such as TCP and UDP applications, and provides high performance and low latency.

question - what is azure function and how it works
ans - Azure Functions is a serverless compute service that allows you to run event-driven code without
    having to manage infrastructure. It works by executing small pieces of code, called "functions," in response 
    to various triggers, such as HTTP requests, timers, or messages from other Azure services.

    a new blob is added, or you can create an HTTP-triggered function that responds to web requests.

Question - difffernce b/w NSG and ASG in azure
ans- NSG (Network Security Group) is a security feature in Azure that allows you to
control inbound and outbound traffic to and from Azure resources. It contains a list of security rules that allow or deny 
traffic based on source and destination IP addresses, ports, and protocols. NSGs are typically associated with subnets or 
 individual network interfaces.
ASG (Application Security Group) is a feature in Azure that allows you to group virtual machines and define security rules
 based on those groups. ASGs provide a way to manage security rules for multiple virtual machines that share 
 similar security requirements. You can create ASGs and then associate them with NSGs to apply security rules to 
 the grouped virtual machines. ASGs are particularly useful for managing security in large environments 
 where you have many virtual machines with similar security needs, as it allows you to simplify the management  
 of security rules by grouping resources together.

question- what is vnet peering in azure
    ans- VNet peering in Azure is a networking feature that allows you to connect two virtual networks (VNets) in the same Azure region. 
    This connection enables resources in the peered VNets to communicate with each other as if they were part of the same network. 
    VNet peering provides low-latency, high-bandwidth connectivity between the peered VNets, allowing for seamless communication and data transfer. 
    It is commonly used to enable communication between different applications or services that are deployed in separate VNets, while still maintaining isolation and security between them. 
    VNet peering can be established using either the Azure portal, Azure PowerShell, or Azure CLI, and it does not require any additional gateways or VPNs to set up.
    3 types of vnet peering in azure
1. Global VNet Peering: This allows you to peer virtual networks across different Azure regions
2. VNet Peering within the same region: This allows you to peer virtual networks within the same Azure region
3. VNet Peering with Azure Virtual WAN: This allows you to peer virtual networks with Azure Virtual WAN, which is a networking service that provides optimized and automated branch connectivity to Azure.

What is the difference between:

Service Endpoint
Private Endpoint

And when will you use each?

Service Endpoint allows a Virtual Network to securely access Azure services over the Azure backbone network. 
The service still uses a public endpoint, but access is restricted to specific VNets, improving security compared 
to open internet access.
Private Endpoint, on the other hand, assigns a private IP from the VNet to the Azure service, making it accessible
only within the private network. It completely removes exposure to the public internet.
The main difference is that Service Endpoint secures traffic to a public endpoint, while Private Endpoint provides full 
private connectivity using a private IP.
In my projects, I use Service Endpoints for simpler setups where moderate security is sufficient, 
and Private Endpoints when strict security and network isolation are required, especially for sensitive resources 
like databases or storage accounts.

question- what is site to site vpn in azure
Answer- A Site-to-Site VPN in Azure is a secure connection between an on-premises
network and an Azure virtual network (VNet) over the public internet. 
It allows you to extend your on-premises network to Azure, 
enabling communication between resources in both environments as if they were on the same local network.
The Site-to-Site VPN is established using a VPN gateway in Azure and a compatible VPN device on-premises.
This connection is typically used for scenarios such as hybrid cloud deployments, where you want to integrate on-premises applications with Azure services, or for securely connecting remote offices to Azure. 
The VPN connection is encrypted, ensuring that data transmitted between the on-premises network and Azure is secure. 
Overall, Site-to-Site VPN provides a reliable and secure way to connect your on-premises network to Azure, allowing for seamless communication and integration between the two environments.


question- what is site to point vpn in azure
Answer- A Point-to-Site VPN in Azure is a secure connection that allows individual devices, 
such as laptops or mobile devices, to connect to an Azure virtual network (VNet) over the   
public internet. It is typically used for remote access scenarios, where users need to securely connect to Azure resources from outside the corporate network. 
With Point-to-Site VPN, users can establish a secure connection to Azure using a VPN client, which authenticates the user and encrypts the traffic between the device and Azure. 
This allows users to access Azure resources as if they were on the same local network, providing secure remote access to applications, data, and services hosted in Azure. 
Point-to-Site VPN is a convenient solution for remote workers, contractors, or anyone who needs to access Azure resources securely from outside the corporate network without the need for a full Site-to-Site VPN connection.

Question:- why can't use managed identity in azure devops pipeline
Answer- Managed Identity cannot be used directly in Azure DevOps pipelines 
because Managed Identities are designed to be used by Azure resources (like VMs, App Services, etc.) 
to authenticate to other Azure services. Azure DevOps pipelines run outside of
 Azure resources, so they do not have a Managed Identity context. 
 Instead, you can use Service Principals or OpenID Connect (OIDC) for authentication in Azure DevOps pipelines to securely access Azure resources.


 Question:- how many type of managed identity in azure
Answer- There are two types of Managed Identity in Azure:
1. System-assigned Managed Identity: This type of identity is automatically created and managed by Azure
    for a specific Azure resource. It is tied to the lifecycle of that resource, meaning that when the resource is deleted, the identity is also deleted. Each resource can have only one system-assigned managed identity.

2. User-assigned Managed Identity: This type of identity is created independently 
of any Azure resource. It can be assigned to one or more Azure resources, 
and it persists even if the resources to which it is assigned are deleted. 
User-assigned managed identities are useful when you need to maintain a consistent 
identity across multiple resources or when you want to manage the lifecycle of 
the identity separately from the resources it is associated with.

what is azure traffic manager and how it works
Answer- Azure Traffic Manager is a DNS-based traffic load balancer that enables you to 
    distribute traffic  across multiple regions and endpoints. It works by directing user requests to 
    the most appropriate endpoint based on various routing methods, such as performance, priority, geographic location, or weighted distribution.
    When a user makes a request to your application, the DNS query is resolved by Azure Traffic Manager, which determines the best endpoint to route the request to based on the configured routing method.
    Azure Traffic Manager continuously monitors the health of your endpoints and automatically reroutes traffic to healthy endpoints
    in case of failures, ensuring high availability and reliability for your applications.
